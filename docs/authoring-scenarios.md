# Authoring scenarios

The scenario model in depth — for humans. (The AI gets the same model from the
[Scenar skill](../.cursor/skills/scenar/SKILL.md).)

A scenario is a **timeline of steps**. Each step shows a snapshot of your UI for
a moment, with optional narration and timed interactions (cursor, typing,
scrolling, zoom). Scenar plays the timeline in the browser and can render
the identical timeline to an MP4.

## The scenario directory

```
my-tour/
├── steps.ts    # the timeline
├── index.tsx   # how to render each step
└── narration/  # generated by `scenar narrate` — don't hand-write
```

`pack`, `render`, and `preview` all consume this shape.

## steps.ts — the timeline

Export `steps: ScenarioStep<T>[]`, where `T` is your per-step data shape:

```ts
import type { ScenarioStep } from "@scenar/core";

export interface StepData {
  url: string;
  screen: "login" | "dashboard";
}

export const steps: ScenarioStep<StepData>[] = [
  {
    delayMs: 0,                              // dwell before reveal; first step = 0
    narration: "Start by signing in.",       // TTS script (build-time only)
    data: { url: "app.acme.cloud/login", screen: "login" },
    interactions: [/* see below */],
  },
];
```

| Field | Required | Meaning |
|-------|----------|---------|
| `delayMs` | yes | milliseconds to dwell before this step is revealed |
| `data` | yes | the snapshot passed to `renderStep` |
| `narration` | no | sentence(s) for TTS; not rendered visually |
| `interactions` | no | timed actions during the step |

## index.tsx — the render function

Export a **pure** `renderStep(data, stepIndex) → ReactNode`. Pick a shell, fill
it with your content:

```tsx
import type { ReactNode } from "react";
import { BrowserView, LoginCardPage, DashboardPage } from "@scenar/react";
import type { StepData } from "./steps";

export function renderStep(data: StepData, stepIndex: number): ReactNode {
  return (
    <BrowserView url={`https://${data.url}`} contentKey={String(stepIndex)}>
      {data.screen === "login"
        ? <LoginCardPage appName="Acme Cloud" /* ... */ />
        : <DashboardPage appName="Acme Cloud" /* ... */ />}
    </BrowserView>
  );
}
```

Always pass `contentKey={String(stepIndex)}` so the shell animates between steps.

## Shells and page templates

`@scenar/react` ships shells that frame the medium and page parts that draw
realistic app UI (CSS-only; no asset files needed):

- **Shells**: `BrowserView`, `TerminalView`, `CodeEditorView`, `MobileView`,
  `ChatView`, `SlideView`, `DashboardView`, `APIClientView`, `DesktopView`.
- **Page templates**: `LoginCardPage`, `DashboardPage`, `SettingsFormPage`,
  `AdminListPage`.
- **Primitives**: `AppBar`, `SideNav`, `FormCard`, `DataTable`, `SettingsForm`,
  `Breadcrumb`, `StatusBadge`, `PulseHighlight`.

For the "real components" path, render *your own* components inside a shell
instead of the templates.

## Interactions

Mark elements in `renderStep` with data attributes, then drive them from a step's
`interactions`:

```tsx
<input data-cursor-target="email" />
<button data-cursor-target="submit">Sign in</button>
```

```ts
interactions: [
  { atPercent: 0.2, type: "set_cursor", target: "email" },
  { atPercent: 0.3, type: "type", target: "email", text: "jordan@acme.cloud" },
  { atPercent: 0.8, type: "click", target: "submit" },
]
```

`StepAction` fields: `atPercent` (0.0–1.0), `type`, `target`, `dragTarget`,
`text`, `typeDelay`, `hoverDuration`, `viewportZoom`, `viewportReset`.

`ActionType`: `set_cursor`, `clear_cursor`, `click`, `type`, `hover`, `drag`,
`scroll_to`, `viewport_transition`.

Targeting attributes:
- `data-cursor-target="id"` — `set_cursor` / `click` / `type` / `hover` / `drag`
- `data-scroll-target="id"` — `scroll_to`
- The engine sets `data-hover` during hovers and `data-dragging` during drags —
  style against them for feedback.

**Timing.** `atPercent` is a fraction of the step's *narration* duration. With
narration, motion syncs to the voiceover; without it, the next step's `delayMs`
is the fallback duration. Narrate first for tight sync.

## The createScenario SDK (type-safe)

For code-first authoring, `createScenario()` checks each step's `props` against
the component registered under its `view`:

```ts
import { createScenario } from "@scenar/sdk";
import { LoginScreen, Dashboard } from "./screens";

export default createScenario({
  viewport: { width: 896, height: 480 },
  views: { login: LoginScreen, dashboard: Dashboard },
  steps: [
    { view: "login", delayMs: 0,
      narrationText: "Sign in to your workspace.",
      props: { email: "jordan@acme.cloud" } },
    { view: "dashboard", delayMs: 2400,
      props: { userName: "Jordan" } },
  ],
});
```

Note `narrationText` (vs `narration` in the directory form) and `props` (vs
free-form `data`).

## YAML / proto scenarios

`scenar validate` checks a scenario **YAML** against the proto schema
(`ai.scenar.scenario.v1`). The `ActionType` strings match the proto enum names,
so YAML interactions use the same `scroll_to` / `set_cursor` / ... values. Load
YAML at runtime with `loadScenarioFromProto()` from `@scenar/sdk`.

## Bundle constraints

`scenar pack` enforces the deploy allowlist:

- Allowed files: `html`, `js`, `css`, `json`, `mp3`, raster images
  (`png`/`jpg`/`jpeg`/`gif`/`webp`/`avif`), `woff2`/`woff`.
- **No SVG files** — inline SVG as a React component or `data:` URI.
- Import raster assets normally (`import logo from "./logo.png"`); Vite emits a
  hashed file at pack time.
- Pack writes `scenario.json` (canonical viewport → embed aspect ratio) and
  `pack-manifest.json` (files + sha256 + content types). Don't hand-edit them.

## Authoring for quality

- One idea per step; 2–3s dwell (`delayMs`) is a comfortable default.
- Narration should read as a narrative when skimmed top to bottom.
- Interactions should mirror what a real user does — don't over-animate.
- Keep narration to one or two present-tense sentences per step.
